# Admin UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Keycloak-protected admin web UI to the authorization server, with two tabs (Users and Applications) and a pastel light/dark theme. Admins edit users, applications, roles and grants; readers only look. A `docker compose` stack runs everything locally.

**Architecture:** New `port.in` use cases are implemented by two domain services, `UserAdminService` and `ApplicationAdminService`, over JDBC `port.out` stores that share a thread-bound transaction. The `adapter/in/web/admin` package runs its own OIDC code flow with Nimbus and keeps the session in an encrypted cookie. A Helidon filter enforces roles and CSRF. Handlers render precompiled jte templates as full pages or htmx fragments.

**Tech Stack:** Java 25, Helidon SE 4.5.5, plain JDBC/Hikari/PostgreSQL 18, Flyway, jte 3.x (precompiled), htmx 2.x (vendored), Nimbus JOSE+JWT 10.10, JUnit 5, AssertJ, REST Assured, WireMock, Testcontainers, Keycloak 26.x, docker compose.

**Spec:** `docs/superpowers/specs/2026-10-18-admin-ui-design.md`. The HTTP contract is `docs/openapi.yaml`; where they differ, the OpenAPI file wins.

## Global Constraints

- Hexagonal rules from `CLAUDE.md`:
  - `application` imports no Helidon, JDBC, jte or adapter classes.
  - Incoming adapters call only `port.in`. Wiring happens only in `Main`.
  - Port interfaces have no `Port`/`UseCase` suffix.
- No CDI, JAX-RS or ORM. Routing is wired in code.
- Primary keys come from `Ids.next()`, so always insert `id`. IDs are rendered and parsed as decimal strings in HTML.
- Schema edits go into `V1__create_authorization_schema.sql` (nothing is deployed). Add `application.responsible VARCHAR(254) NOT NULL`.
- **Name pattern:** application and role names match `[A-Za-z0-9][A-Za-z0-9._-]{0,99}`.
- **Username:** trimmed, 1 to 255 characters.
- **Email:** at most 254 characters, matches `^[^@\s]+@[^@\s]+\.[^@\s]+$`.
- **Description:** optional, trimmed, at most 2000 characters. Blank is stored as `NULL`.
- **At least one grant:** every user always has at least one grant. A change that would orphan users deletes them in the same transaction, only when `confirmedUserIds` equals the set computed in that transaction. Otherwise nothing changes and the server answers 409 with a new confirmation dialog.
- **Roles:** writes require the realm role `authz-admin`; reads accept `authz-admin` or `authz-reader`.
- **CSRF:** every non-GET `/admin` request needs an `X-CSRF-Token` header matching the session.
- **Headers:** every `/admin` and `/oidc` response sets `Cache-Control: no-store`. Unhandled exceptions stay a bare 500, logged only.
- **Content-Security-Policy** on `/admin`: `default-src 'self'; img-src 'self' data:; frame-ancestors 'none'`. This forbids inline scripts and styles in templates, so htmx's indicator styles are turned off through `htmx-config`.
- **Startup:** the server must start without a database and without Keycloak. OIDC discovery is fetched lazily on the first login.
- **Admin UI is optional:** it is enabled only when `admin.oidc.issuer` is configured. Otherwise `/admin` is not routed and a WARNING is logged. Existing API tests do not configure it.
- Existing authorization-API invariants and tests stay unchanged and green.
- Vanilla CSS only, with htmx served from `/admin/static/`. No CDN and no JS build.
- Conventional Commits, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- With Colima, run tests with `TESTCONTAINERS_HOST_OVERRIDE=localhost TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`.

## Review Focus

1. **Concurrent grant during an orphaning delete.** Alice gets a new role while her last role is being deleted, and she must survive. Pinned by `deletesOnlyUsersStillWithoutRolesAtCommit` (Task 2).
2. **Forged or tampered session cookie.** Altered bytes, a different key, or an expired session must be treated as no session (redirect) and never cause a 500. Pinned by `tamperedOrExpiredSessionIsIgnored` (Task 5).
3. **Open redirect via `returnTo`.** `https://evil.example` and `//evil.example` must fall back to `/admin`. Pinned by `returnToOutsideAdminFallsBackToAdmin` (Task 5).
4. **HTML injection through names and descriptions.** A description of `<script>alert(1)</script>` must render escaped. Pinned by `escapesUserProvidedText` (Task 6).
5. **Roles from another application in a grant form.** Posting `applicationId=billing` with a `crm` role ID must give 422 and change nothing. Pinned by `rejectsRolesOfAnotherApplication` (Task 3).

- Produces (ports):
  ```java
  interface Transactions { <T> T inTransaction(Supplier<T> work); default void run(Runnable work) {...} }
  interface UserStore {
      void insert(UserId id, Username username);
      boolean rename(UserId id, Username username);
      boolean delete(UserId id);
      Optional<UserAccess> find(UserId id);
      List<UserAccess> findAll();                                   // sorted by username
      List<UserSummary> deleteUsersWithoutRoles(Collection<UserId> candidates); // returns those actually deleted
  }
  interface ApplicationStore {
      void insert(ApplicationId id, ApplicationName name, Email responsible, Description description);
      boolean update(ApplicationId id, ApplicationName name, Email responsible, Description description);
      boolean delete(ApplicationId id);
      Optional<ApplicationDetails> find(ApplicationId id);
      List<ApplicationSummary> findAll();                           // sorted by name
      void insertRole(ApplicationId app, RoleId id, NewRole role);
      boolean updateRole(ApplicationId app, RoleId id, NewRole role);
      boolean deleteRole(ApplicationId app, RoleId id);
      Set<RoleId> roleIds(ApplicationId app);
  }
  interface GrantStore {
      void grant(UserId user, Set<RoleId> roles);                   // ON CONFLICT DO NOTHING
      boolean revoke(UserId user, RoleId role);
      List<UserSummary> usersLosingAllRoles(Set<RoleId> removed, Optional<UserId> onlyUser);
  }
  ```
- `JdbcTransactions(DataSource)` implements `Transactions` and exposes `Connection current()`, which throws `IllegalStateException` outside a transaction. Nested `inTransaction` calls join the outer one. It commits on return and rolls back on any throwable. The stores take a `JdbcTransactions`.
- `UniqueViolations.translate(SQLException)` maps SQLState `23505` constraint names to fields:
  - `app_user_username_key` → `"username"`
  - `application_name_key` → `"name"`
  - `uk_role_application_name` → `"roleName"`
  - Anything else becomes `PersistenceException`.

`usersLosingAllRoles` query (an algorithm the signature does not determine):
```sql
SELECT u.id, u.username FROM app_user u
WHERE (?::bigint IS NULL OR u.id = ?)
  AND EXISTS (SELECT 1 FROM user_role ur WHERE ur.user_id = u.id AND ur.role_id = ANY(?))
  AND NOT EXISTS (SELECT 1 FROM user_role ur WHERE ur.user_id = u.id AND ur.role_id <> ALL(?))
ORDER BY u.username
```
`deleteUsersWithoutRoles` runs `DELETE FROM app_user u WHERE u.id = ANY(?) AND NOT EXISTS (SELECT 1 FROM user_role WHERE user_id = u.id) RETURNING id, username`. This re-checks at delete time, so a user granted a new role concurrently survives.

**Interfaces:**
- **Config** (`admin.oidc.*` and `admin.*` in `application.yaml`, with env vars in comments):
  - `admin.oidc.issuer`
  - `admin.oidc.client-id`
  - `admin.oidc.client-secret`
  - `admin.oidc.redirect-uri`
  - `admin.oidc.discovery-base-url`: optional. Discovery is fetched from `<it or issuer>/.well-known/openid-configuration`.
  - `admin.oidc.allow-insecure`: default `false`. When false, it requires https on the issuer and discovery URLs.
  - `admin.session-key`: base64, 32 bytes, required.
  - `admin.session-duration`: default `PT8H`.
  - `admin.cookie-secure`: default `true`.
- `OidcSettings.fromConfig(Config admin)` returns `Optional<OidcSettings>`, empty when `admin.oidc.issuer` is missing.
- `enum AdminRole { ADMIN("authz-admin"), READER("authz-reader") }`
- `record AdminSession(String username, Set<AdminRole> roles, String csrfToken, Instant expiresAt)` with `boolean canWrite()`.
- `record LoginState(String state, String nonce, String codeVerifier, String returnTo, Instant expiresAt)`
- `SessionCodec(byte[] key)`:
  - `String encode(AdminSession)` and `Optional<AdminSession> decode(String)`.
  - The same pair exists for `LoginState`.
  - Uses JWE `dir` + `A256GCM`, carrying a claims JSON.
  - `decode` returns empty on any parse or decrypt failure, or on expiry.
- `OidcClient(OidcSettings, HttpClient)`:
  - `URI authorizationUri(LoginState)` uses `response_type=code`, `scope=openid`, PKCE `S256`, `state` and `nonce`.
  - `AdminIdentity exchange(String code, LoginState)` posts to the token endpoint with client_secret_basic.
  - The ID token is verified with Nimbus `DefaultJWTProcessor` and a `RemoteJWKSet` (or `JWKSourceBuilder`) on the discovered `jwks_uri`. The checks are:
    - RS256 only;
    - exact `iss` = settings issuer;
    - `aud` contains the client ID;
    - `exp` is mandatory;
    - `nonce` equals the state's nonce.
  - The username comes from `preferred_username`, and roles from the `roles` string array claim.
  - `URI endSessionUri()`
  - Discovery is fetched lazily on first use and cached.
- `record AdminIdentity(String username, Set<AdminRole> roles)`
- **Cookies:**
  - `AUTHZ_ADMIN_SESSION`: `Path=/`.
  - `AUTHZ_ADMIN_LOGIN`: `Path=/oidc`, `Max-Age=600`.
  - Both are `HttpOnly; SameSite=Lax`, and `Secure` when `cookie-secure`.
- **`AdminAuthFilter`**, a Helidon `Filter` applied to paths under `/admin` except `/admin/login` and `/admin/static/**`:
  - With no valid session:
    - an `HX-Request` gets 401 with `HX-Redirect: /admin/login?returnTo=<path>`;
    - any other request gets 302 to that URL.
  - A session without any role → 403.
  - A non-GET request without an `X-CSRF-Token` equal to the session's token (constant-time compare) → 403.
  - A non-GET request without `canWrite()` → 403, except `POST /admin/logout`, which readers may use too.
  - Otherwise it registers the `AdminSession` in `request.context()` and proceeds.
- **`LoginRoutes`:**
  - `GET /admin/login?returnTo=` accepts only paths starting with `/admin` and not with `//`; anything else becomes `/admin`.
  - `GET /oidc/redirect` returns 400 on a missing or mismatching state or cookie, or a failed exchange. On success it clears the login cookie and redirects 302 to `returnTo`.
  - `POST /admin/logout` returns 204, clears the session cookie, and sets `HX-Redirect` to the end-session URI with `client_id` and `post_logout_redirect_uri=<origin>/admin`.
- **`Main`:** routes the admin UI only when `OidcSettings` is present. The session key is decoded at startup, and a missing key fails startup only when the admin UI is configured.
- **Test support:**
  - `FakeKeycloak extends` (or wraps) `TestIdentityProvider`. It stubs `/.well-known/openid-configuration`, `/auth`, `/token`, `/jwks` and `/logout`.
  - `stubNextLogin(String username, String... roles)` returns an ID token whose nonce is read from the latest `/auth` request.
  - `AdminClient.login(serverPort, keycloak, username, roles…)` returns `record AdminCookies(String session, String csrf)`. It drives `GET /admin`, the `/auth` redirect and `/oidc/redirect`, then reads the CSRF token from `<meta name="csrf-token">` on `/admin`. Create a minimal `UsersRoutes` here whose `GET /admin` renders a stub page with that meta tag; Task 6 replaces it.
